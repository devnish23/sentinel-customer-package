Troubleshooting Guide

Version 3.0.1 · Updated 2026-06-01

Installation Issues

setup.bat fails: "Node.js not found"

Install Node.js 20 LTS from nodejs.org, then re-run setup.bat. Make sure to check "Add to PATH" during installation.

npm install fails: ECONNREFUSED or ETIMEDOUT

Your machine may require a proxy. Set: set HTTP_PROXY=http://proxy:port then re-run. Or download dependencies on an internet-connected machine and copy node_modules.

Build fails: TypeScript error

Ensure Node.js is 20+. Run node -v to verify. If correct, delete portal/node_modules and re-run setup.

Portal Won't Start

Port 3000 already in use

Re-run setup.bat/setup.sh and choose a different port, or kill the process using port 3000: netstat -ano | findstr :3000 then taskkill /PID [pid] /F

Blank white page after opening portal

Open browser DevTools (F12) → Console. Common cause: API_BASE_URL is wrong. Re-run setup and verify the Hub URL is correct and reachable.

Portal shows "Failed to load dashboard"

The Hub is not reachable. Check: (1) Hub service is running, (2) Hub URL in config matches exactly, (3) Firewall allows TCP 8080/8443, (4) No proxy intercepting the request.

Agent Issues

Agent shows OFFLINE

Full checklist: KB-004 — Agent Offline Troubleshooting

Agent not appearing in portal after install

Wait 60 seconds for first heartbeat. If still missing: check agent service is running (sc query MinifraAgent), verify Hub URL entered during agent install.

Antivirus quarantined minifra-agent.exe

Full resolution steps: KB-006 — Antivirus Exclusions

License Issues

License shows EXPIRED

Contact licensing@minifra.com with your License ID to renew. During the grace period (default 30 days), the system continues operating with a warning.

Offline activation fails: "Invalid activation blob"

The blob may have been copied with line breaks. Paste it as a single unbroken string. If still failing, request a new blob from licensing@minifra.com.

License shows HARDWARE_MISMATCH

The Hub machine was changed or re-imaged. Follow the hardware re-binding process: KB-008 — Hardware Binding Migration

Recording Issues

Recording status stays STOPPED despite policy

Check: (1) Policy is APPROVED and assigned to the agent, (2) Agent has sufficient local storage, (3) captureMethod is not set to an invalid value — use "Auto".

Recording chunks show HASH_MISMATCH

This may indicate tampering. Check Alerts for TAMPER events. If it's a false positive (e.g. after AV scan), acknowledge the alert and verify the recording was intact before the scan.

Export Issues

Export approval button greyed out

You are logged in as the same user who created the request. Self-approval is blocked by policy. A different user with Reviewer role must approve.

Chain-of-custody verification fails

One or more chunks may be corrupted. Check Vault for the original chunks. If hash mismatch is confirmed, the recording may have been tampered with — escalate to your Security team.

Hub Issues

Hub fails to start after reboot

Full resolution steps: KB-009 — Hub Startup Failure

Hub log: "certificate verify failed"

TLS cert has expired or the CA is not trusted. Renew/replace the cert and restart the MinifraHub service. For self-signed certs on agents, add the CA cert to Windows Trusted Root store.

Still Stuck?

Collect a support bundle and contact the support team:

  • Email: support@minifra.com
  • Include your License ID and Hub version (http://localhost:8080/health)
  • Attach the support bundle — see KB-014
