Tamper Detection — What Triggers an Alert

Minifra Sentinel monitors agents for signs of tampering.

Events that trigger SUSPECTED status:
  1. Agent binary hash mismatch — minifra-agent.exe has been modified.
  2. Service stopped unexpectedly — killed without using the Hub API.
  3. Config file modified outside the Hub — config.json edited directly on disk.
  4. Recording chunk hash mismatch — stored chunk SHA-256 does not match manifest.
  5. Clock manipulation — system clock jumped beyond the allowed threshold.
  6. Uninstall attempt blocked — uninstall protection kicked in.

What to do when an agent shows SUSPECTED
  1. Do NOT dismiss without investigation.
  2. Customer Portal → Alerts → review the tamper alert details.
  3. Collect a support bundle from the affected agent.
  4. Check agent logs at C:\ProgramData\Minifra\Agent\logs\
  5. Escalate to your Security team if hash mismatch is confirmed.
  6. Contact support@minifra.com with the support bundle.

Common false positives
  - Antivirus scanning/modifying the binary (solution: add exclusions — see KB-006)
  - Windows Update replacing runtime DLLs
  - Legitimate config push from Hub (should NOT trigger tamper — if it does, open a case)

Clearing a false positive
  After investigation: Alerts → Acknowledge → Close
  The audit log records who cleared the alert and when.
